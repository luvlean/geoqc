# DECISIONS.md — журнал решений

Формат: `D-NNN` — дата — решение — обоснование — последствия.

## D-001 — 2026-09-26 — Выбор AOI делегирован Data Agent, критерии зафиксированы
Открытый снимок GSD ≤ 0.5 м с лицензией, допускающей обработку (OpenAerialMap CC-BY 4.0, Maxar Open Data CC BY-NC 4.0), AOI 5–10 км² со смешанной застройкой и хорошим покрытием OSM. Сначала проверяется покрытие OpenAerialMap по РФ; при отсутствии — зона за рубежом. Процедура выбора — скрипт `geoqc data search-aoi`, кандидаты — `reports/aoi_candidates.json`. Итоговый выбор дописывается сюда Data Agent как D-001a.

## D-002 — 2026-09-26 — Esri World Imagery только как подложка
Тайлы Esri/Bing/Яндекс — лицензированный контент, массовая выгрузка и обучение на них запрещены условиями использования и §7 плана. Разрешено: XYZ-подложка в Leaflet и QGIS с атрибуцией и API-ключом (`ARCGIS_API_KEY` в `.env`). Детекция и метрики — только по открытому снимку. Пайплайн принимает любой GeoTIFF на входе, компания может подставить свои лицензионные снимки.

## D-003 — 2026-09-26 — CI: GitHub Actions
Один workflow: ruff, pytest с сервисом PostGIS, сборка Docker-образа, проверка ноутбуков. GitLab CI не делается.

## D-004 — 2026-09-26 — Универсальный ноутбук дообучения
`notebooks/train_finetune.ipynb` автоопределяет CUDA / MPS / CPU; Colab-ячейки помечены и пропускаются локально; данные подаются архивом `make bundle`. Обучение запускает студент.

## D-005 — 2026-09-26 — Предразметка + правка в QGIS вместо разметки с нуля
Annotation Agent генерирует черновые контуры из вторичного источника (Microsoft/Google footprints) или бейзлайн-детекций; студент правит и подтверждает каждый объект (`verified=true`) в QGIS. Эталон остаётся независимым от OSM. Риск смещения к предразметке снижается слепой повторной разметкой 10 % тайлов (G2).

## D-006 — 2026-09-26 — Одно рабочее дерево вместо веток на агента
Агенты работают параллельно в одном каталоге; изоляция обеспечивается матрицей владения директорий (`docs/CONTRACTS.md §1`), коммит — один на задачу агента. В промышленной среде правило «одна задача — одна ветка» восстанавливается без изменений кода.

## D-007 — 2026-09-26 — Пакетная раскладка `src/geoqc/<module>` вместо `src/<module>`
Единый устанавливаемый пакет упрощает импорты, тесты и Docker. Имена модулей совпадают с планом: `data cv matching eval api` + `annotation`.

## D-008 — 2026-09-26 — Таблица `matches` отделена от `discrepancies`
Пары с IoU ≥ 0.5 нужны для G5 (средний IoU), но не являются расхождениями. В `discrepancies` — только три класса MVP.

## D-009 — 2026-09-26 — Конфиг по модулям `config/<module>.yaml`
Избегает конфликтов записи при параллельной работе; `geoqc.config.load_config()` собирает всё в один словарь.

## D-010 — 2026-09-26 — Порт PostGIS 5433
5432 занят локальным Postgres.app.

## D-011 — 2026-09-26 — Разбиение multipart-детекций в `matching run`
CV пишет MultiPolygon из одной части; многочастные появляются только после `make_valid`. `geoqc_split_multipart_detections` разбивает их до сопоставления, id таких строк меняются. Принято: сопоставление всегда идёт после записи детекций.

## D-012 — 2026-09-26 — Вспомогательные таблицы `det_suppressed` и `discrepancy_features`
Живут в `sql/002_matching.sql`. NMS не удаляет строки из `buildings_det`, а помечает их в `det_suppressed`. Eval и App исключают подавленные id при подсчёте детекций.

## D-013 — 2026-09-26 — `geometry_mismatch` не строго 1:1
Две детекции могут указывать на один объект OSM. Для очереди расхождений это допустимо: оператор видит обе.

## D-001a — 2026-09-26 — AOI: Пушкин, Отдельный парк, Тярлево
`geoqc data search-aoi` выбрал UAV-ортофото OpenAerialMap `6101142e5a90f10006fd3038` (Sergey Astakhov, CC-BY 4.0, 2021-07-26, GSD 0.073 м, UTM 36N). AOI 5.55 км², в bbox 2352 здания OSM. Смесь застройки покрывает все страты отбора тайлов, в отличие от кандидатов в Невском районе. Снимок пересэмплируется до 0.3 м. Кандидаты и причины — `reports/aoi_candidates.json`.

## D-014 — 2026-09-26 — Снимок OSM от 2026-07-24
Overpass-зеркало отдало данные на 2026-07-24 (кэш `data/raw/osm_2026-07-24.json`, ODbL). Дата фиксируется в `manifest.json` → `osm.snapshot_date`. Снимок сделан 2021-07-26, поэтому часть `missing_on_image` — здания, построенные после съёмки, а не ошибки карты. Это учитывается при разборе очереди и в тексте работы.

## D-015 — 2026-09-27 — SpaceNet 2 как внешний размеченный датасет
Из whitelist плана §9 взят SpaceNet 2 Buildings (train; Париж, Шанхай, Вегас по 100 тайлов, seed 42): публичный бакет без
регистрации, CC BY-SA 4.0, 0.3 м — как наши тайлы. INRIA требует регистрации. Назначение — smoke-обучение до готовности `val`,
опционально подмешивание к train и образец для своей разметки. Метрики на SpaceNet в работу не идут: G3 — только на `val`,
порог — только по holdout `val`. Разбор — `docs/datasets/spacenet2.md`.

## D-016 — 2026-10-17 — Одно здание — один полигон
Части одного здания с крышами разной высоты (веранда, пристройка, корпус) размечаются одним полигоном; раньше — отдельными.
Модель, OSM (`building:part` в слой не попадает) и Microsoft footprints дают здание цельным контуром, и разрезанный эталон
при сопоставлении 1:1 по IoU давал ложный пропуск. Отдельные полигоны — только для разных зданий с общей стеной.
Правило принято до начала разметки val, `PROTOCOL.md` §1, §3.

## D-017 — 2026-10-25 — Базовые веса без дообучения
`yolov8m-building-seg-1996bc04` с порогом 0,20 (sweep на val) даёт на проверенной разметке val F1 0,748 (P 0,721, R 0,778)
и проходит G3. Дообучение на `val+spacenet` отклонено: 9 из 11 тайлов val ушли бы в обучение, и честно сравнить модели
было бы не на чем. Веса и порог зафиксированы до оценки test; если test не пройдёт G4, это фиксируется в отчёте с причиной.

## D-018 — 2026-10-27 — Подавление осколков и вложенных кусков крыши перед сопоставлением
Верификация v1 (50 расхождений, `reports/verification_v1.csv`): точность очереди 0,54, `missing_in_map` 0,44. 8 из 10
ошибок модели в `missing_in_map` — кусок крыши, детектированный поверх уже найденного здания. В очереди 253 из 966
`missing_in_map` были меньше 12 м²: части после разбиения мультиполигонов обходят минимум `cv.vectorize`. Решение: после
NMS подавлять детекции < 12 м² (`small`) и детекции, на ≥ 80 % лежащие внутри другой, в ≥ 4 раза большей (`nested`);
вложенная детекция с IoU ≥ 0,5 к эталону остаётся (иначе терялись 11 совпадений внутри склеенных кварталов). Очередь
1432 → 1161, совпадений 1064 → 1064. Фильтр подобран по выборке v1, поэтому G6/G7 считаются по новой выборке v2;
v1 сохранена в `reports/*_v1.*` и приводится в работе как первая итерация.

## D-019 — 2026-10-27 — Footprints Microsoft как псевдоразметка для дообучения
Своей разметки (126 зданий val) для дообучения мало, а val должен остаться честной проверкой G3. `geoqc cv prepare-microsoft`
берёт footprints Microsoft (ODbL, источник из whitelist плана §9) на тайлах вне val/test и их 8 соседей (перекрытие 64 px),
без тайлов с nodata > 10 % и без зданий: 55 тайлов, 676 зданий, holdout для ранней остановки — 20 % этих же тайлов.
Контуры не проверены по нашему снимку (часть мелких домов не обведена), поэтому прогоны на них — эксперименты: веса
сравниваются с зафиксированными по val через `predict --weights`, конфиг меняется только после сравнения. Побочный эффект:
слагаемое «совпадение со вторым источником» в confidence перестаёт быть полностью независимым от модели.

## D-020 — 2026-10-27 — Дообучение не улучшило модель, остаются базовые веса
Сравнение на val (разметка val в обучении не участвовала; `reports/finetune_experiments_val.json`), лучший F1 по порогу:
базовые веса 0,774 (P 0,79, R 0,76), дообучение только на SpaceNet 2 — 0,731, только на footprints Microsoft — 0,722
(ранняя остановка на 31-й эпохе). SpaceNet — другой сенсор и застройка; Microsoft — неточные контуры и пропуски мелких
домов, модель перенимает их (precision и mean IoU падают). Зафиксированные веса D-017 не меняются; веса экспериментов
лежат в `models/*-ft-*.pt` и в конфиг не попадают. Дальнейший рост — только на проверенной разметке нашей зоны.

## D-021 — 2026-10-27 — Разделение train / val / test вместо val / test
До первой оценки test (её не было: нет `reports/metrics_test.json`) разметка переразделена: бывший val (11 тайлов,
126 зданий) → `train`, на нём дообучается модель; бывший test (13 тайлов, 190 зданий) → `val`, на нём подбираются
гиперпараметры, порог и масштаб, по нему же считается G3; новый `test` — 8–10 новых тайлов с разной застройкой, не
соседних с train/val, выбор детерминированный (seed 42, `annotation add-test-tiles`). Причина: своя разметка — единственные
данные, улучшающие модель (D-020), а подбор параметров на тех же тайлах, что и обучение, нечестен. G4/G5 считаются один раз
на новом test. Повторная разметка для G2 (3 тайла) остаётся при своих тайлах в новых наборах. Модуль `cv` читает разметку
train и val, разметка test ему по-прежнему запрещена.

## D-022 — 2026-10-28 — Первый проход разметки test сделан ИИ-ассистентом, проверяет студент
По просьбе студента черновики Microsoft на 10 тайлах test прошли автоматическую и визуальную предобработку ассистентом
до ручной проверки. Детекции модели не использовались ни на каком шаге, чтобы test не зависел от модели. Шаги:
контуры уточнены по исходному снимку 7 см классическим GrabCut (`scripts/experiments/refine_drafts.py`, на train
приблизил черновики к ручной разметке: F1 0,51 → 0,56, mean IoU 0,76 → 0,81); по визуальному просмотру удалены
ложные контуры (грузовики, бак, тень, кусты), склеены секции одного здания (D-016), добавлены 25 пропущенных построек,
8 мест помечены «спорно» (`scripts/experiments/apply_test_review.py`). Все объекты `verified=false`, в `notes` указано,
что проверить; эталоном test становится только после поштучной проверки и правки студентом в QGIS. Риск — эффект
привязки к готовым контурам; в работе это указывается как ограничение.

## D-023 — 2026-10-28 — Модель и порог выбираются по F1, взвешенному по площади
Для очереди расхождений пропущенный многоквартирный дом или склад важнее пропущенного сарая, а обычный F1 их не
различает. Метрика выбора — $\mathrm{F1}_a$ (§3а `docs/metrics_and_formulas.md`): здания весят своей площадью;
считается в `geoqc eval detection` (`f1_area`) и задаёт порог в `threshold-sweep` (`cv.sweep.select_by: f1_area`).
Гейты G3–G5 не меняются (обычный F1 и mean IoU) и отчитываются рядом. Критерий принят до оценки `test`.

## D-024 — 2026-10-28 — Рабочая модель: train + AIRS, вход 768, порог 0,50
Кандидаты на `val` по F1 по площади (D-023): базовая 0,869; train + AIRS 0,978 (порог 0,50); + RID2 с закрашенными
крупными зданиями 0,978 (0,40); + RID2 с полной разметкой 0,973 (0,45). RID2 (Нидерланды, CC BY 4.0) отобран по
ошибкам модели на мелких постройках (400 окон, без коллективных садов) — на нашем `val` поднял их полноту (12–30 м²:
0,57 → 0,71; 30–100 м²: 0,89 → 0,94–0,98), но снизил точность на них (0,68 → 0,64–0,65). При равенстве главной
метрики приоритет — крупные здания:
train + AIRS находит все 74 здания `val` от 100 м² без ложных срабатываний среди них, у вариантов с RID2 — по одному
ложному. Выбрана `yolov8m-building-seg-ft-ours-airs-f87c92a9`; резервная копия — релиз GitHub
`weights-ours-airs-f87c92a9`. Очередь перестроена (1161 → 1050 расхождений, совпадений с OSM 1064 → 1120),
верификация v2 сохранена как `reports/*_v2.*`, для v3 сделана новая выборка.

## D-025 — 2026-10-28 — Куски зданий OSM не попадают в очередь
Верификация v3 (50 расхождений, `reports/verification_v3.csv`, модель D-024): точность очереди 0,42, G6/G7 не пройдены.
15 из 29 ошибок модели — «выделила лишнюю часть цельного здания»: модель (train + AIRS) обводит здание OSM по частям,
каждая часть с IoU < 0,5 уходит в `geometry_mismatch` или `missing_in_map`. Детекция, на ≥ 80 % лежащая внутри одного
здания OSM, оказалась ошибкой модели в 15 случаях из 16. Решение: такие детекции подавлять (`ref_fragment`, сопоставление
с IoU ≥ 0,5 не затрагивается), а здание, в котором они лежат, не считать `missing_on_image`. Цена — пропуск случаев, когда
контур OSM крупнее реального здания (1 из 16 в v3). Очередь 1050 → 1002 (gm 103 → 73, mim 646 → 631, moi 301 → 298),
совпадений 1120 → 1120. Правило подобрано по v3, поэтому G6/G7 считаются по новой выборке v4; v3 сохранена в
`reports/*_v3.*`.
Итог v4 (`reports/verification.csv`): точность 0,64 (v3 — 0,42, v2 — 0,58), precision@20 0,55; G6/G7 не пройдены.
По классам: `missing_in_map` 0,89, `missing_on_image` 0,53, `geometry_mismatch` 0,47. Остаток ошибок модели: склейка
соседних зданий в одну детекцию (8 из 18) и здания OSM, которых модель не нашла (7 из 18, все в топ-20 очереди).

## D-026 — 2026-10-29 — Детекция на любом загруженном снимке в вебе
Вкладка «Снимок» и `POST /detect`: снимок перетаскивается в окно или выбирается из файловой системы, модель из
`config/cv.yaml` находит здания, результат открывается поверх карты. Модель обучена на 0,3 м/пикс, поэтому снимок
сначала приводится к этому разрешению: размер пикселя берётся из привязки GeoTIFF, для обычной картинки — из поля
«Пиксель, м» или 0,3 по умолчанию (интерфейс об этом предупреждает). Дальше — тот же путь, что для AOI: тайлы 512 с
перекрытием 64, векторизация и склейка контуров на стыках (`geoqc.cv.image_detect`). Лимиты — `detect` в
`config/api.yaml` (300 МБ, 6144 px после приведения); результат не пишется в базу и не попадает в очередь.

## D-027 — 2026-10-29 — Удалён код отработавших экспериментов и неиспользуемых веток

обучение шло локально на MPS; скрипты RID2 (`rid2_prepare.py`, `rid2_train.py`) — модели не выбраны (D-024);
`progress.sh`, запасной путь `make db-init`, неиспользуемая `rect_from_bbox`. Ноутбук `train_finetune.ipynb` — только
