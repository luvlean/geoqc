# AIRS — внешний размеченный датасет (эксперимент)

Зачем: проверить, улучшает ли подмешивание чужой аэрофотосъёмки с ручной разметкой крыш нашу модель
(D-020: SpaceNet и footprints Microsoft не помогли). Ноутбук анализа — `notebooks/airs_eda.ipynb`,
метрики — `reports/external_airs_eda.json`, ночной прогон обучения — `scripts/experiments/airs_night.py`.

## Источник и лицензия

| | |
|---|---|
| Набор | AIRS — Aerial Imagery for Roof Segmentation (Chen, Wang, Wu, Wu, Guo, Waslander; ISPRS J. Photogramm. Remote Sens. 147, 2019) |
| Сенсор | аэрофото LINZ 2015–2016, RGB uint8, 10 000×10 000 px, 7,5 см, EPSG:2193 (NZTM) |
| Территория | Крайстчерч, Новая Зеландия, 1046 тайлов (train 857 / val 94 / test 95), 580 км² |
| Разметка | бинарная маска крыш (`label/*.tif`), `*_vis.tif` — визуальные копии |
| Лицензия | снимки и контуры зданий LINZ — CC BY 4.0, «Crown Copyright Reserved»; у упаковки датасета лицензия не указана |
| Загрузка | <https://www.kaggle.com/datasets/atilol/aerialimageryforroofsegmentation> (≈ 18 ГБ после распаковки; нужен вход в Kaggle) |
| Где лежит | распаковать в `data/raw/external/airs/` (`train/`, `val/`, `test/` с `image/` и `label/`) или указать `AIRS_DIR`; каталог в `.gitignore` |

Набора нет в whitelist плана §9: используется как эксперимент с атрибуцией LINZ и ссылкой на статью; данные в git
не попадают.

## Что показал анализ

Графики (покрытие крышами и карта тайлов, площади и форма зданий, цвет, примеры) — в выводах ноутбука
`notebooks/airs_eda.ipynb`; файлы `docs/datasets/figures/airs_*` он пересоздаёт при запуске, в git они не хранятся.

| Показатель | AIRS | наш AOI (`train`+`val`) |
|---|---|---|
| Тайлы без крыш / с nodata > 10 % | 166 (16 %) / 110 (11 %) | — |
| Медианная площадь здания | 127 м² | 58 м² |
| Доля 12–30 м² | 14 % | 35 % |
| Доля > 500 м² | 2 % | 8 % |
| Плотность на застроенных тайлах | 884 на км² | 558 на км² |
| Прямоугольность (медиана) | 0,89 | 0,81 |
| Потеря зданий при 7,5 см → 0,3 м | 1,0 % | — |
| Доля зелени на тайле | 35 % | 60 % |
| Средняя яркость крыш | 150 | 171 |

Выводы:

1. Данные полные и согласованные; наборы train/val/test перемешаны по городу. Пустые (16 %) и краевые (11 %) тайлы
   для обучения отбрасываются.
2. Уменьшение до нашего разрешения 0,3 м почти не склеивает соседние крыши (−1 %): подготовка ×4 корректна.
3. AIRS покрывает дома 100–500 м², но почти не содержит мелких дачных построек (у нас 35 %) и крупных многоэтажек
   (у нас 8 %). Ожидаемо: лучше контуры частных домов, без выигрыша на сараях и панельках.
4. Разметка по крышам аккуратная в жилой застройке; в промзонах соседние склады слиты в одну маску.
5. Наш снимок заметно зеленее и ярче; нужны цветовые аугментации (включены), при неудаче — выравнивание гистограмм.
6. Ночной прогон оценивать не только по общему F1 на val, но и по полноте в классах площади.

## Подготовка для обучения (`scripts/experiments/airs_night.py`)

1. Пары из `train/image` и `train/label` (val/test AIRS не используются), детерминированный порядок (seed 42).
2. Снимок и маска уменьшаются ×4 до 0,3 м (усреднение; маска — порог 0,5), режутся на чипы 512 px.
3. Чип берётся, если ≥ 90 % пикселей снимка не пустые и в нём есть здание; здания — связные компоненты ≥ 12 м²,
   контуры → YOLO-seg полигоны. До 2 чипов на тайл, всего 1500.
4. Обучение: наш `train` ×10 + чипы AIRS, ранняя остановка по нашему `val`, вход 768, аэро- и цветовые аугментации;
   итог — `data/interim/external/airs/night_result.json` в сравнении с базовой моделью при входе 768 (F1 0,792).
