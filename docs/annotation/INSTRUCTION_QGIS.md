# Разметка эталона в QGIS: пошаговая инструкция

**Нужно ли размечать руками?** Да, но только проверять и править готовые черновики, а не рисовать с нуля.
Без ручного эталона нельзя честно посчитать точность детекции (G3–G5): OSM — это то, что мы проверяем, и эталоном он быть не может (D-005).

Объём работы — около 24 тайлов по 512×512 пикселей (примерно 150×150 м каждый), половина в `val`, половина в `test`.
Плюс повторная слепая разметка 2–3 тайлов для G2.
**Оценка времени — 1.5–2 часа**: 3–5 минут на тайл с черновиком и около 10 минут на тайл повторной разметки.

Что считать зданием и как вести контур, описано в [PROTOCOL.md](PROTOCOL.md). Прочитайте его перед началом, это 5 минут.

## 0. Подготовка (один раз)

Нужны QGIS 3.28+ (на macOS — `/Applications/QGIS.app`) и выполненные шаги данных.

```bash
cd ~/Desktop/geoqc
make up            # PostGIS
make data          # снимок, тайлы, OSM, вторичные контуры
make labels-prep   # отбор тайлов, черновики val/test, проекты QGIS
```

После `make labels-prep` появятся:

| Файл | Что это |
|---|---|
| `data/labels/tiles_split.csv` | выбранные тайлы и их выборка `val`/`test` |
| `data/labels/recheck_tiles.csv` | тайлы для повторной слепой разметки |
| `data/labels/<split>/draft.geojson` | черновые контуры, `verified=false` |
| `data/labels/<split>/work.gpkg` | рабочий файл: слои `buildings` (копия черновика) и `recheck` (пустой) |
| `data/labels/<split>/qgis/annotation_<split>.qgz` | готовый проект QGIS |

Если `.qgz` не создался (другая ОС или нет QGIS.app), команда `geoqc annotation qgis-project --split val` выведет ручные шаги сборки проекта. Стили слоёв лежат рядом в `qgis/*.qml`.

## 1. Открыть проект

Откройте `data/labels/val/qgis/annotation_val.qgz` двойным кликом или через Project → Open.
Сначала размечайте `val`, потом `test`: порядок и приёмы одинаковые.

Слои сверху вниз:

| Слой | Вид | Назначение |
|---|---|---|
| `recheck` | пунктир, фиолетовый, скрыт | только для повторной разметки (шаг 5) |
| `buildings` | оранжевый — не проверен, зелёный — проверен | **единственный слой, который вы правите** |
| `tiles_frame` | жёлтая рамка, голубая для тайлов повтора | границы тайлов с подписью `tile_id` |
| `osm_buildings` | синий пунктир | подсказка, **не эталон** и не копируется |
| `secondary_buildings` | серые точки, скрыт | источник черновика, для сравнения |
| `Esri World Imagery` | скрыт, есть только при `ARCGIS_API_KEY` | ориентир, **обводить по нему нельзя** (лицензия, D-002) |
| `aoi_cog` | снимок | **обводить только по нему** |

В проекте уже включены прилипание к вершинам и сегментам и запрет пересечений для `buildings` и `recheck`.
Проверить их можно в Project → Snapping Options. Клавиша `S` включает и выключает прилипание.

## 2. Как проходить тайл

1. В `tiles_frame` откройте таблицу атрибутов (`F6`), выберите тайл и нажмите «Zoom map to selected rows». Удобный масштаб — 1:500–1:800.
2. Выберите слой `buildings` и включите редактирование: значок карандаша «Toggle Editing» на панели инструментов.
3. Пройдите тайл и исправьте черновик по протоколу:
   - **лишний контур** (навес, дерево, тень, машина): выделите его инструментом «Select Features» и нажмите `Delete`;
   - **неточная форма**: инструмент Vertex Tool (`V`). Тяните вершину мышью, двойной клик по ребру добавляет вершину, выделенная вершина удаляется клавишей `Delete`;
   - **пропущенное здание**: Add Polygon Feature (`Cmd+.` на macOS, `Ctrl+.` на Windows и Linux). Левый клик ставит вершины, правый клик завершает. В форме оставьте значения по умолчанию, `source` будет `manual`;
   - **два здания слиплись в один контур**: панель Advanced Digitizing → Split Features, проведите линию разреза поперёк контура;
   - **одно здание разбито на части**: выделите части и выберите Edit → Merge Selected Features;
   - **контур сильно не тот**: быстрее удалить его и нарисовать заново.
4. Отменить действие — `Cmd+Z` / `Ctrl+Z`. Перемещать карту — с зажатым пробелом.
5. Сохраняйте правки регулярно кнопкой «Save Layer Edits» (дискета рядом с карандашом). Правки пишутся в `work.gpkg`.

## 3. Поставить `verified=true`

Отметка ставится, когда тайл пройден целиком.

1. Выделите все объекты тайла в `buildings`: Vector → Research Tools → Select by Location. Условие «intersect», сравнение со слоем `tiles_frame` и галка «Selected features only», где в `tiles_frame` выделен текущий тайл.
   Можно проще: инструмент «Select Features by Polygon» или прямоугольник по рамке тайла.
2. Откройте таблицу атрибутов `buildings` и нажмите «Open Field Calculator» (значок счёт).
3. Отметьте «Only update N selected features» и «Update existing field», поле `verified`, выражение `true`. Нажмите OK.
4. Контуры тайла станут зелёными. Сохраните правки слоя.

Проверка в конце: в таблице атрибутов `buildings` нажмите «Select features using an expression» и введите `"verified" = false`.
Должно найтись 0 объектов. Если что-то нашлось, это недопроверенные контуры: пройдите их или удалите, если это не здания.

## 4. Когда `val` закончен

Сохраните правки слоя и проект, закройте QGIS или откройте проект `test`:
`data/labels/test/qgis/annotation_test.qgz`. Повторите шаги 2–3 для `test`.

## 5. Повторная слепая разметка (G2)

Делайте её не сразу, а лучше на следующий день, чтобы не рисовать по памяти.

1. Тайлы повтора — в `data/labels/recheck_tiles.csv`. В `tiles_frame` у них голубая рамка.
2. **Выключите** слои `buildings`, `osm_buildings`, `secondary_buildings`. Черновик и прошлую разметку не смотрите.
3. Включите слой `recheck`, включите у него редактирование и **нарисуйте все здания тайла с нуля** по тому же протоколу.
4. `verified` в `recheck` не проверяется. `annotator` можно оставить пустым.
5. Сохраните правки слоя. Повторите для тайлов повтора в `test`, если они есть в `recheck_tiles.csv`.

G2 — средний IoU пар объектов «основная разметка — повторная» на этих тайлах. Порог — 0.80.
Если G2 не проходит, то протокол применяется непоследовательно: чаще всего это пристройки и здания под кронами.
Пересмотрите такие случаи в основной разметке, а не подгоняйте повторную.

## 6. Выгрузка и проверка

```bash
make labels-validate
# то же самое по шагам:
geoqc annotation finalize --split val --annotator "Жуков"
geoqc annotation validate --split val
geoqc annotation finalize --split test --annotator "Жуков"
geoqc annotation validate --split test
```

`finalize` превращает `work.gpkg` в контрактные файлы `buildings.geojson` и `recheck.geojson`.
Он чинит геометрию, обрезает объекты по тайлу, удаляет объекты меньше 12 м² и приводит поля к контракту.
Прошлая версия `buildings.geojson` сохраняется как `.bak`.

`validate` пишет `reports/annotation.json` и печатает сводку. Код выхода `0` — разметка принята, `1` — отклонена.
С флагом `--strict` предупреждения и непройденный G2 тоже дают ненулевой код.

Как читать `reports/annotation.json`:

| Поле | Смысл |
|---|---|
| `splits.<split>.status` | `accepted` или `rejected` |
| `splits.<split>.errors` / `warnings` | список проблем с `code`, `tile_id` и номером объекта |
| `splits.<split>.stats` | число объектов, тайлов, площади |
| `splits.<split>.agreement` | G2 по этому сплиту: пары, TP/FP/FN, средний IoU |
| `annotation.agreement_iou`, `agreement_f1` | G2 по всем сплитам, идёт в `reports/metrics.json` |
| `gates.G2.passed` | пройден ли порог |

## 7. Типичные ошибки валидации

| Код | Причина | Что делать |
|---|---|---|
| `not_verified` | остался объект с `verified=false` | шаг 3, выражение `"verified" = false` |
| `duplicate_overlap` | два контура перекрываются больше чем на 50 % меньшего | удалить дубль |
| `small_overlap` | небольшое наложение соседей (предупреждение) | поправить общую стену через Vertex Tool |
| `invalid_geometry` | самопересечение («бабочка») | Vector → Geometry Tools → Check Validity, перерисовать вершины |
| `min_area` | объект меньше 12 м² | удалить, если не здание; `finalize` удаляет такие сам |
| `outside_tile` / `unknown_tile` | объект вне тайлов своего сплита | удалить или перенести; `finalize` обрезает по тайлу |
| `tile_without_labels` | в тайле нет ни одного здания | проверить: если зданий правда нет, это нормально; иначе разметить |
| `recheck_missing` | нет `recheck.geojson` (предупреждение) | выполнить шаг 5, иначе G2 не посчитается |
| `recheck_tiles_missing` | в тайле повтора нет объектов слоя `recheck` | дорисовать повтор на этом тайле |
| `g2_below_target` | G2 ниже 0.80 | см. конец шага 5 |

## 8. Чего не делать

- Не копировать контуры из `osm_buildings` в `buildings`. Эталон, списанный с OSM, сделает проверку OSM бессмысленной.
- Не обводить по слою Esri: лицензия Esri запрещает производные данные, а снимок другой даты и со своим смещением.
- Не смотреть метрики модели на `test` до финального прогона: тестовая выборка оценивается один раз.
- Не править `buildings.geojson` руками после `finalize`: правьте `work.gpkg` в QGIS и запускайте `make labels-validate` снова.
