# Глава 1. Введение

## 1.1 Актуальность

Векторные картографические данные — OpenStreetMap, кадастровые слои, корпоративные базы — устаревают быстрее, чем обновляются: здания сносят и строят, контуры оцифрованы по старым или смещённым снимкам. Типовые дефекты слоя зданий — пропущенные объекты, объекты, которых больше нет, и контуры с существенным расхождением геометрии. Ручная сверка вектора со снимком по всей территории дорога и не масштабируется; при этом данные высокого разрешения (аэрофотосъёмка, коммерческие спутники, открытые программы OpenAerialMap и Maxar Open Data) стали доступны, а методы сегментации зданий на снимках достигли практически применимого качества.

Прикладная ценность — сместить работу картографа с просмотра всей территории на проверку короткого списка кандидатов, ранжированного по уверенности. Мера ценности — доля реальных ошибок карты среди топ-$N$ кандидатов (precision@N).

## 1.2 Цель

Разработать и экспериментально оценить воспроизводимый алгоритм верификации слоя зданий: по снимку зоны интереса детектировать здания, сопоставить их с векторным слоем и сформировать очередь расхождений с классом, уверенностью и визуализацией на карте.

## 1.3 Задачи

1. Проанализировать проблему качества геоданных, существующие решения и методы сегментации зданий (гл. 2).
2. Подготовить данные: выбрать зону интереса и открытый снимок с допустимой лицензией, получить срез OSM, привести слои к единым контрактам (CRS, тайлы, PostGIS), проверить геопривязку (гл. 3).
3. Сформировать независимую эталонную разметку зданий (val/test) с протоколом и контролем согласия (гл. 3).
4. Реализовать детекцию и векторизацию зданий, сопоставление 1:1 с вектором, классификацию расхождений и скоринг уверенности (гл. 4).
5. Реализовать хранение в PostGIS, API и веб-карту для просмотра и подтверждения расхождений; обеспечить воспроизводимость одной командой (гл. 5).
6. Измерить качество по заранее зафиксированным критериям (гейты G1–G9), выполнить ручную верификацию очереди, анализ ошибок и сравнение с альтернативным источником контуров (гл. 6).

## 1.4 Объект и предмет

Объект — процесс контроля качества векторных геопространственных данных о зданиях. Предмет — алгоритмы и программные средства автоматизированного выявления расхождений между векторным слоем и данными дистанционного зондирования методами компьютерного зрения.

## 1.5 Границы работы

В скоупе: один класс объектов (здания), одна зона 5–10 км² со смешанной застройкой, три класса расхождений (`missing_in_map`, `missing_on_image`, `geometry_mismatch`), статическая оценка по одному снимку и одному срезу вектора. Вне скоупа: другие классы объектов, автоматическая правка OSM (запрещена Automated Edits code of conduct), покрытие города, обучение модели с нуля, мониторинг во времени.

## 1.6 Формат выполнения

Работа выполнена как оркестр ИИ-агентов с фиксированными зонами ответственности и контрактами данных под контролем студента (human-in-the-loop): студент выполняет разметку эталона, при необходимости — дообучение модели, ручную верификацию очереди и принимает результаты на контрольных точках. Все числовые результаты порождены кодом репозитория и хранятся в `reports/`; в записке они приводятся со ссылкой на ключ `reports/metrics.json`.
