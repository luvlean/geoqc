# Глава 7. Заключение

## 7.1 Итоги

1. Построен воспроизводимый пайплайн «снимок + вектор → детекция → сопоставление → очередь расхождений»: `make all` поднимает окружение, получает данные, детектирует здания, сопоставляет их с OSM и формирует отчёт; статус воспроизводимости — `{{metrics.reproducibility.make_all_passed}}`.
2. Сформирован независимый эталон зданий (`{{metrics.dataset.n_gt_val}}` + `{{metrics.dataset.n_gt_test}}` объектов на `{{metrics.dataset.n_tiles_val}}` + `{{metrics.dataset.n_tiles_test}}` тайлах) с протоколом разметки и измеренным согласием (IoU `{{metrics.annotation.agreement_iou}}`).
3. Измерено качество детекции на `test`: F1 `{{metrics.detection.test.f1}}`, средний IoU совпавших `{{metrics.detection.test.mean_iou_matched}}`; качество очереди — precision `{{metrics.discrepancies.precision_overall}}`, precision@`{{metrics.discrepancies.precision_at_n.n}}` `{{metrics.discrepancies.precision_at_n.value}}`. Статус гейтов G1–G9 — табл. 6.8; непройденные гейты описаны с причинами и fallback.
4. Реализованы API (GeoJSON, MVT, тайлы снимка, смена статуса, экспорт) и веб-карта для сценария «зона → расхождения → статус → экспорт»; очередь экспортируется в формате, пригодном для MapRoulette/JOSM.
5. Все числа порождены кодом и лежат в `reports/`; тестовая разметка не участвовала в обучении и подборе порогов (подтверждено статическими тестами QA).

## 7.2 Ограничения

- Разновременность снимка и среза OSM: часть `missing_*` — реальные изменения; без разновременных снимков снос и ошибку карты не различить.
- Контур крыши vs фундамента при off-nadir съёмке, тени и растительность смещают и скрывают контуры; выбор протокола разметки влияет на IoU.
- Одна зона, один снимок, один класс объектов: обобщение на другие регионы, сезоны и типы застройки не проверялось.
- Метрики G6/G7 зависят от объёма и качества ручной верификации (≥ 50 объектов одним верификатором).
- Вычислительный бюджет: CPU/MPS или один GPU уровня T4; обучение с нуля не рассматривалось.
- Закрытые подложки (Esri/Bing) — только для визуального сравнения; качество на них не измерялось.

## 7.3 Направления развития

1. **Мониторинг во времени**: пары снимков разных дат, класс `changed`, разделение сноса и ошибки карты.
2. **Другие классы объектов**: дороги, водные объекты, сооружения — те же контракты сопоставления при замене модели.
3. **Масштабирование на город**: пакетный инференс по COG-мозаике, партиционирование таблиц по тайлам, очередь задач (Airflow), MVT-кэш.
4. **Интеграция с процессом правки**: загрузка очереди в MapRoulette, обратная связь вердиктов валидаторов для переобучения скоринга (learning-to-rank на признаках п. 4.6).
5. **Признаки для скоринга**: NDVI при наличии NIR, высота из DSM/теней, история правок OSM.
6. **Замена детектора**: сравнительный эксперимент с готовыми контурами (Microsoft/Google) показывает, когда достаточно сопоставления без собственной модели.
