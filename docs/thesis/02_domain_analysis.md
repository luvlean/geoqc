# Глава 2. Анализ предметной области

## 2.1 Проблема качества геоданных

Качество векторного слоя описывается полнотой (все ли объекты присутствуют), актуальностью (соответствие текущему состоянию местности), позиционной и геометрической точностью (положение и форма контуров) и корректностью атрибутов. Для слоя зданий практически значимы три дефекта, которые и образуют классы расхождений данной работы:

- объект есть на местности (снимке), но отсутствует в слое — пропуск (`missing_in_map`);
- объект есть в слое, но отсутствует на снимке — снесён, ошибочно оцифрован или не распознан на снимке (`missing_on_image`);
- объект присутствует в обоих источниках, но контуры существенно расходятся — смещение, устаревшая форма, слияние/разделение (`geometry_mismatch`).

Источник неоднозначности — разновременность: снимок и срез вектора относятся к разным датам, поэтому часть расхождений отражает реальные изменения, а не ошибки. В OpenStreetMap данные распространяются по ODbL [1], а массовые автоматические правки регулируются Automated Edits code of conduct [2]: инструмент контроля качества должен формировать задачи для ручной проверки, а не изменять данные напрямую.

Существующие инструменты контроля качества OSM — Osmose, KeepRight, OSM Inspector — работают преимущественно с топологией, тегами и внутренней согласованностью данных [3]; сопоставление со снимком в них остаётся ручной операцией. Платформа MapRoulette [4] распределяет микрозадачи проверки между участниками: типовая задача — «посмотреть объект и снимок, исправить или отметить как ложную». Это задаёт целевой формат выхода настоящей работы — очередь задач с геометрией и приоритетом.

## 2.2 Существующие наборы контуров зданий, полученные из снимков

**Microsoft GlobalMLBuildingFootprints** [5] — открытый (ODbL) набор контуров зданий, полученных сегментацией спутниковых снимков глубокими нейросетями с последующей полигонизацией; распространяется по квадкеям, для регионов указана оценка точности. **Google Open Buildings** [6, 7] — контуры зданий для Африки, Южной и Юго-Восточной Азии, Латинской Америки и Карибского бассейна, полученные моделью сегментации на снимках высокого разрешения; каждому полигону приписана уверенность; лицензия CC BY 4.0 / ODbL.

Оба набора решают задачу *получения* контуров, но не задачу *верификации* конкретного слоя: они не сопоставлены с OSM объект-к-объекту, не классифицируют расхождения и не ранжируют их для проверки. В настоящей работе такие наборы используются двумя способами: как черновая предразметка для ускорения ручной разметки эталона (с последующей правкой каждого объекта) и как второй источник для признака согласия в скоринге и для сравнительного эксперимента (гл. 6).

Коммерческие сервисы мониторинга изменений по спутниковым снимкам (change detection) ориентированы на разновременные пары снимков и закрытые данные; их лицензии, как правило, не допускают массовой выгрузки тайлов и обучения на них. По этой причине в работе картографические подложки Esri/Bing/Яндекс используются только для визуального сравнения, а детекция выполняется на открытом снимке (`DECISIONS.md`, D-002).

## 2.3 Методы сегментации зданий на снимках

**Семантическая сегментация.** Архитектура U-Net [8] — энкодер-декодер со skip-соединениями — стала базовой для сегментации зданий на аэроснимках; современные реализации (например, `segmentation_models_pytorch`) используют предобученные энкодеры. Выход — бинарная маска «здание/фон», требующая последующей полигонизации и разделения слипшихся объектов.

**Instance-сегментация.** Семейство YOLO в реализации Ultralytics (YOLOv8-seg) [9] выдаёт маску и уверенность для каждого экземпляра, что удобно для последующего 1:1 сопоставления с полигонами карты и для скоринга; модели работают в реальном времени на GPU и приемлемо на CPU для тайлов 512×512.

**Фундаментальные модели.** Segment Anything (SAM) [10] сегментирует произвольные объекты по промптам (точки, рамки) без обучения на целевом домене; для зданий применяется с автоматическими промптами или в связке с детектором и уступает специализированным моделям по границам крыш, но полезна как инструмент разметки.

**Эталонные наборы данных.** INRIA Aerial Image Labeling [11] — аэроснимки 0.3 м с масками зданий для нескольких городов, проверяющий обобщение между городами; SpaceNet [12] — спутниковые снимки с векторными контурами зданий (челленджи 1–2 и последующие). Оба допускают дообучение и используются как источники предобученных чекпоинтов.

**Оценка.** Стандартом сравнения объектов является IoU (индекс Жаккара); объект считается найденным при IoU ≥ 0.5 — конвенция, идущая от PASCAL VOC [13]. Для полигонов после векторизации применяются те же IoU, precision, recall и F1 (гл. 4, `docs/metrics_and_formulas.md`).

## 2.4 Постобработка и сопоставление

Маска переводится в полигоны растровой полигонизацией (`rasterio.features.shapes` / `gdal_polygonize`), контуры упрощаются алгоритмом Дугласа–Пекера [14] с допуском в метрах, мелкие фрагменты отбрасываются по площади. Сопоставление детекций с векторным слоем — задача о назначениях на матрице IoU: жадный выбор по убыванию IoU или оптимальный венгерский алгоритм [15]; в PostGIS кандидаты отбираются пространственным индексом GiST по `ST_Intersects` [16].

## 2.5 Выводы по главе

1. Инструменты QA OSM не сопоставляют вектор со снимком; ML-наборы контуров не верифицируют конкретный слой; change-detection-сервисы закрыты по данным и лицензиям. Ниша работы — объектное сопоставление снимка и вектора с классификацией и ранжированием расхождений для ручной проверки.
2. Для детекции достаточно предобученных моделей сегментации (YOLOv8-seg, U-Net) с дообучением на открытых данных и части собственной разметки; обучение с нуля не требуется.
3. Ground truth должна быть независимой от проверяемого слоя: OSM не может служить эталоном, требуется ручная разметка с контролем согласия.
4. Выход системы — очередь задач в формате, пригодном для MapRoulette/JOSM; автоматическая правка исключается.
