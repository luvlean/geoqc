# ТЗ T4 — CV Agent: детекция зданий, векторизация, ноутбук дообучения

**Цель.** `make detect` заполняет `detections.geojson` и `buildings_det`; студент может дообучить модель в универсальном ноутбуке.

**Запрет.** Не читать `data/labels/test/` ни в коде, ни в ноутбуке, ни в экспериментах. Пороги подбирать только на `val`.

**Выходы.**
- `src/geoqc/cv/`: `weights.py` (`fetch-weights`: попытка скачать предобученный чекпоинт сегментации зданий с Hugging Face Hub, например `keremberke/yolov8m-building-segmentation` — проверить существование и лицензию; fallback — `yolov8m-seg.pt` от Ultralytics как архитектура для дообучения + честная запись в карточке, что без дообучения он здания не детектирует; sha256 весов → `model_version`), `predictor.py` (интерфейс `Predictor.predict(tile: np.ndarray) -> list[Mask]` с реализациями `UltralyticsSegPredictor`, `SmpUnetPredictor` (segmentation_models_pytorch, чекпоинт из ноутбука); выбор устройства cuda/mps/cpu; батчинг; half на cuda), `vectorize.py` (маска → полигоны `rasterio.features.shapes`, перенос в CRS тайла через transform, склейка на перекрытиях: объединение пересекающихся полигонов соседних тайлов с `unary_union` и учёт score как max/area-weighted, Douglas–Peucker `simplify(tolerance)` в метрах, фильтр min_area_m2, `make_valid`, → MultiPolygon EPSG:4326), `dataset.py` (`export-dataset`: `labels/val/buildings.geojson` + тайлы → формат YOLO-seg (txt полигоны) и бинарные маски для U-Net; сплит val на train/holdout внутри val 80/20 с фиксированным seed — test не трогать), `sweep.py` (`threshold-sweep --split val`: F1 при IoU ≥ 0.5 для сетки порогов, используя `geoqc.eval.detection_metrics` если доступен, иначе локальную реализацию по формулам §4 → `reports/threshold_sweep_val.json`; выбранный порог → `config/cv.yaml`), `bundle.py` (`bundle`: zip с `data/tiles/*.tif` для val-тайлов + всех тайлов, `labels/val/`, `tiles_split.csv`, `config/`, без `labels/test` → `data/interim/bundle.zip`), `cli.py` (`fetch-weights`, `predict --split all|val|test [--to-db] [--limit N]`, `export-dataset`, `threshold-sweep`, `bundle`).
- `config/cv.yaml`: backend, weights path/URL, model_version, conf_threshold, imgsz 512, batch, device auto, simplify_tolerance_m 0.5, min_area_m2 12, tile_overlap_merge_iou.
- `models/MODEL_CARD.md` (§3.10).
- `notebooks/train_finetune.ipynb` — **универсальный**: ячейка окружения (`IN_COLAB`, устройство cuda/mps/cpu, `torch.backends`), Colab-ячейки помечены `# COLAB ONLY` и завёрнуты в `if IN_COLAB:` (монтирование Drive, установка пакетов, распаковка `bundle.zip`); локально — путь к репозиторию. Данные: `export-dataset` результат; опционально INRIA/SpaceNet (ячейка со ссылкой и лицензией, выключена по умолчанию). Обучение Ultralytics YOLOv8-seg (`model.train(... amp=True, cache='ram'|'disk', workers, imgsz=512, patience, resume)`) и/или SMP U-Net с AMP, `torch.compile` опционально, чекпоинт каждой эпохи, resume, ранняя остановка, логирование в csv; финальная ячейка — экспорт весов в `models/`, sha256 → `model_version`, обновление `config/cv.yaml` и `MODEL_CARD.md`, прогон `threshold-sweep` на holdout части val. Ноутбук без outputs в git (`nbstripout`), markdown-ячейки на русском, код на английском; проходит `nbqa ruff`. Отдельно `notebooks/README.md`: как запускать локально и в Colab, ожидаемое время, что сделать после обучения.
- `tests/cv/`: векторизация синтетической маски (два квадрата → два полигона, площадь, CRS), склейка полигонов на перекрытии двух тайлов, фильтр min_area, `Predictor` мок → полный `predict` на 2 синтетических тайлах без сети (маркер не network), `bundle` не содержит `labels/test`, детерминизм сплита `export-dataset`.

**Реальный прогон.** Когда `data/tiles/` появится (Data Agent), выполнить `geoqc cv fetch-weights` и `geoqc cv predict --split all --to-db` на mps/cpu, записать в LOG время, число детекций, `model_version`. Если тайлов ещё нет — оставить готовые команды и написать об этом в LOG; координатор попросит прогнать позже.

**DoD.** Тесты зелёные, `predict` детерминирован при фиксированном seed, карточка модели честная, ноутбук валиден (`nbformat.validate`) и без outputs, README модуля с описанием пайплайна и формулами (IoU склейки, DP-упрощение).
