# ТЗ T6 — Eval Agent: метрики, гейты, анализ ошибок

**Цель.** Все цифры проекта порождаются кодом этого модуля и попадают в `reports/metrics.json` по схеме §3.9; гейты G1–G9 проверяются автоматически.

**Выходы.**
- `src/geoqc/eval/`: `detection_metrics.py` (чистые функции над shapely: `iou(a,b)`, `match_one_to_one(gts, preds, iou_thr, method='greedy'|'hungarian')`, `precision_recall_f1(tp,fp,fn)`, `mean_iou(pairs)`; вход — GeoDataFrame/список геометрий в метрической CRS; работа по тайлам сплита из `tiles_split.csv`, обрезка детекций по тайлам сплита), `georef.py` (чтение `reports/georef.json`), `discrepancy_metrics.py` (`verification-sample`: стратифицированная выборка ≥ 50 расхождений, ≥ 15 на класс где возможно, из `discrepancies` по `confidence DESC` + случайные → `reports/verification_sample.csv` со столбцами `id,class,confidence,iou,lon,lat,verdict,comment`, `verdict ∈ {map_error, model_error, image_issue, unsure}` заполняет студент; `discrepancies --verification`: precision по классам = `map_error / (n − unsure)`, precision_overall, precision@N для N из конфига по топ-N по confidence среди проверенных), `compare_secondary.py` (детекции vs второй источник как альтернативный «детектор»: P/R/F1 против ручной разметки test — обоих), `gates.py` (`gates`: собрать все промежуточные json, вычислить `passed` по `config/quality_gates.yaml` (op/target), `git_commit`, `reproducibility`/`tests` флаги берутся из аргументов `--make-all-passed`, `--tests-passed --n-tests`; → `reports/metrics.json`; вывод таблицы гейтов в консоль), `error_analysis.py` (`error-analysis`: FP/FN по тайлам и стратам, распределение площадей ошибок, IoU-гистограмма, топ-10 худших тайлов, рендер PNG примеров тайл+GT+pred в `reports/figures/`, шаблон markdown с разделами «Тени», «Сложные крыши», «Плотная застройка», «Растительность», «Граница тайла» — заполняется **только** цифрами из расчёта, без гипотез там, где нет данных; → `reports/error_analysis.md`), `cli.py`.
- `config/eval.yaml`: iou_threshold 0.5, match_method, precision_at_n [10, 20, 50], sample_size 50, per_class_min 15, seed.
- `tests/eval/`: IoU на квадратах (1, 1/3, 0), 1:1 сопоставление (жадное vs венгерское на конфликте), P/R/F1 крайние случаи (0 предсказаний, 0 GT), mean IoU, precision@N на синтетическом csv, гейты (op `<=`, `>=`, `==`, отсутствующая метрика → passed=false, note), схема metrics.json содержит все ключи §3.9.

**Одноразовость test.** `detection --split test` пишет `reports/metrics_test.json` и отказывается перезаписывать без `--force` с записью причины в файл `reports/metrics_test.runs.log`.

**Реальный прогон.** Если есть `data/labels/val/buildings.geojson` с verified и `detections.geojson` — посчитать val и записать в LOG. Если разметки ещё нет (студент правит), прогнать на `draft.geojson` только как smoke-тест с пометкой «не метрика».

**DoD.** Тесты зелёные, `geoqc eval gates` работает даже при частично отсутствующих отчётах (заполняет null и passed=false с note), README модуля со **всеми формулами** в явном виде (LaTeX/Markdown) и описанием схемы metrics.json.
