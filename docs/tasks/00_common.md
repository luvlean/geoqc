# Общие требования ко всем ТЗ

1. Прочитать `docs/CONTRACTS.md` полностью и своё ТЗ. Границы записи — §1 контрактов, нарушать нельзя.
2. Окружение: `~/Desktop/geoqc/.venv` (Python 3.11), все пакеты из `requirements-dev.txt` уже установлены, пакет `geoqc` установлен в editable-режиме. `pip install` запрещён — недостающие пакеты записывать в LOG.
3. БД: `docker compose up -d db` (порт 5433), схема — `sql/001_schema.sql`, тестовая БД `geoqc_test`. Применить схему: `.venv/bin/python -c "from geoqc.db import connect, apply_schema; ..."` или `geoqc matching init-db` (когда появится).
4. Код и комментарии — English; README, docstring-описания тестовых кейсов — русский. Перед завершением: `ruff format <свои пути> && ruff check --fix <свои пути>`, `pytest tests/<module> -q`.
5. Никаких выдуманных результатов. Если что-то не удалось — честно в LOG и в README модуля.
6. Не коммитить в git — коммиты делает координатор. Не трогать `PLAN.md`, `DECISIONS.md`; предложения по решениям — в LOG.
7. README модуля `src/geoqc/<module>/README.md` — обязателен: назначение, входы/выходы, команды CLI с примерами, параметры `config/<module>.yaml`, формулы (если есть), зависимости от других модулей, ограничения, что должен знать агент, который будет продолжать работу.
8. В конце — один блок в `LOG.md` (§10 контрактов) через `cat >> LOG.md <<'EOF' ... EOF`.
9. Лимит: одна задача, без расширения скоупа. Вопросы координатору — в финальном отчёте, не блокировать работу.
