# ТЗ T9 — Docs Agent: README, формулы и метрики, план документации, записка, презентация

**Цель.** Проект передаётся компании и защищается как курсовая: документация точная, без выдуманных цифр, с явными формулами.

**Выходы.**
- `README.md` (корень, русский): что это, архитектура (mermaid из плана), быстрый старт (`scripts/bootstrap.sh` или `make install`, `.env`, `make up db-init`, `make data detect match eval demo`), структура репозитория, контрольные точки человека (правка разметки в QGIS, ноутбук обучения, верификация), лицензии и атрибуция (OSM ODbL, источник снимка из `data/manifest.json`, Esri только подложка — ссылка на D-002), ограничения, ссылки на README модулей и `docs/`. Инструкция запуска должна соответствовать реальному `Makefile` и CLI (проверить командами `--help`).
- `docs/DOCUMENTATION_PLAN.md` — **действия по описанию документации**: перечень документов, кто/когда обновляет, чек-лист «каждая цифра → путь в reports/ → ключ json», правила формул (нотация, единицы, CRS), правила скриншотов/рисунков, как генерировать таблицы метрик из `reports/metrics.json` (скрипт `scripts/render_metrics_table.py` — написать здесь же в docs как сниппет или запросить у координатора).
- `docs/metrics_and_formulas.md` — все формулы проекта в явном виде с обозначениями и примерами на числах: IoU, 1:1 сопоставление (жадное и венгерское), TP/FP/FN, Precision/Recall/F1, mean IoU, классы расхождений и пороги, формула confidence (взять из `src/geoqc/matching/README.md` и `scoring.py`, не придумывать), precision по классам, precision@N, G2-согласие, G1-смещение, DP-упрощение и min_area; таблица гейтов G1–G9 с целевыми значениями и указанием ключа `metrics.json`.
- `docs/architecture.md` — компоненты, потоки данных, CRS, таблицы БД, последовательность make-таргетов, где что лежит.
- `docs/thesis/` — пояснительная записка по §11 плана: `00_outline.md` и файлы по главам с текстом-заготовкой; числа — только плейсхолдерами вида `{{metrics.detection.test.f1}}` с указанием источника; глава «Анализ предметной области» — реальные ссылки (Microsoft GlobalMLBuildingFootprints, Google Open Buildings, MapRoulette, INRIA, SpaceNet, YOLOv8-seg, SAM, U-Net) без выдуманных DOI.
- `docs/presentation/outline.md` — 10–12 слайдов: проблема → решение → архитектура → данные и разметка → метрики → демо → ограничения → развитие; на каждом слайде — что показать и откуда взять цифру.
- Проверка README модулей: каждый `src/geoqc/*/README.md`, `notebooks/README.md`, `data/labels/README.md` существует и содержит разделы из `docs/tasks/00_common.md` п.7; отсутствующие/неполные — перечислить в LOG (не править чужие).

**Правила.** Ни одной цифры метрик, не взятой из `reports/`. Если отчёта нет — плейсхолдер. Лаконично, без воды. Формулы в Markdown/LaTeX.
