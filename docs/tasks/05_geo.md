# ТЗ T5 — Geo Agent: сопоставление, классификация расхождений, скоринг

**Цель.** `make match` заполняет `matches` и `discrepancies` в PostGIS по контракту; логика проверена тестами на синтетических геометриях.

**Выходы.**
- `sql/002_matching.sql`: функции `geoqc_iou(geom, geom, metric_srid int) → double` (пересечение/объединение в метрической CRS через `ST_Transform`), `geoqc_candidate_pairs(model_version text, metric_srid int, min_iou double)` — все пары ref×det с `ST_Intersects` через GiST и IoU ≥ min_iou; `geoqc_match_greedy(model_version, metric_srid, iou_match)` — жадное 1:1 по убыванию IoU, запись в `matches`; классификация → `discrepancies` (geometry_mismatch: лучшая пара 0.1 ≤ IoU < 0.5 при отсутствии match у обоих; missing_in_map: det без пары с max IoU < 0.1; missing_on_image: ref без пары), идемпотентно по `model_version` (DELETE перед INSERT). Только `source='osm'` как эталон; `source in ('microsoft','google')` — второй источник для скоринга.
- `src/geoqc/matching/`: `matcher.py` (Python-обёртка запуска SQL + опциональный венгерский алгоритм `scipy.optimize.linear_sum_assignment` на матрице IoU по кластерам пересечений — выбор в конфиге `algorithm: greedy|hungarian`), `scoring.py` (формула `confidence`: для `missing_in_map` = `w_score·score + w_area·area_norm + w_sec·agree_secondary`; для `missing_on_image` = `w_area·area_norm + w_sec·(1 − overlap_secondary) + w_ctx·(1 − max_iou_any_det)`; для `geometry_mismatch` = `w_score·score + w_iou·(1 − iou) + w_area·area_norm`; нормировка в [0,1], `area_norm = clip(log(area/min_area) / log(max_area/min_area), 0, 1)`; веса в `config/matching.yaml`; формула записана в README и воспроизводится в тестах на конкретных числах), `edge_cases.py` (объекты, пересекающие границу AOI → флаг и понижение confidence; мультиполигоны — по частям; дедупликация детекций с IoU > 0.7 между собой до сопоставления), `export.py` (→ `reports/discrepancies.geojson`, §3.8), `cli.py` (`init-db` применяет `sql/` через `geoqc.db.apply_schema`; `run --model-version [--algorithm]`; `export`; `stats`).
- `config/matching.yaml`: iou_match 0.5, iou_mismatch_min 0.1, dedup_iou 0.7, algorithm, weights, min_area_m2, max_area_m2, aoi_edge_buffer_m.
- `tests/matching/` (маркер `db`, фикстура `db_conn`): синтетические сценарии в метрической CRS с переводом в 4326 — полное совпадение (match, IoU=1), сдвиг на половину (IoU=1/3 → geometry_mismatch), det без ref (missing_in_map), ref без det (missing_on_image), два det на один ref (1:1 — второй становится missing_in_map или отбрасывается дедупом), мультиполигон, идемпотентность повторного `run`, венгерский vs жадный на конфликтном примере. Без БД — чистые тесты `scoring.py` на числах.

**DoD.** `geoqc matching init-db && geoqc matching run --model-version <v>` работает на тестовой БД; при наличии реальных `buildings_ref`/`buildings_det` (от Data/CV) — реальный прогон, `stats` в LOG (число по классам). README модуля с формулами (IoU, скоринг, алгоритм 1:1) и SQL-примерами.
