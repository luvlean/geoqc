# ТЗ T8 — QA/Review Agent: ревью, интеграционные тесты, воспроизводимость

**Цель.** Независимо подтвердить, что модули соответствуют `docs/CONTRACTS.md`, тесты покрывают критические сценарии, ограничения плана соблюдены.

**Действия.**
1. Ревью каждого модуля (`src/geoqc/*`, `sql/`, `web/`, `notebooks/`, `Makefile`, `Dockerfile`, `.github/`): соответствие контрактам §3, §6, §8; обработка ошибок; SQL-инъекции (параметризация); идемпотентность; детерминизм (seed); секреты не в коде; лицензии/атрибуции в README; заявления в README соответствуют коду.
2. Ограничения: статический тест `tests/integration/test_constraints.py` — в `src/geoqc/cv/`, `notebooks/`, `src/geoqc/matching/` нет строк `labels/test`; в репо нет `.env`, ключей (`ARCGIS_API_KEY=` с непустым значением), URL тайлов Esri/Bing/Google в модулях `data`/`cv`; `sql/001_schema.sql` не изменён относительно контракта (сравнить с описанием таблиц в CONTRACTS).
3. `tests/integration/test_pipeline_synthetic.py` (маркер `db`): синтетический сквозной прогон — сгенерировать растр 2×2 тайла с «зданиями»-прямоугольниками, разметку, «детекции» через мок-Predictor, загрузить ref/det в тестовую БД, `matching run`, `eval detection`, `eval gates` → проверить схему `metrics.json` и ожидаемые классы расхождений на заранее известных объектах.
4. `tests/integration/test_cli.py`: `geoqc --help`, каждый sub-app отвечает на `--help`.
5. Расширить `tests/conftest.py` при необходимости (общие фикстуры синтетического растра/тайлов).
6. Прогон: `ruff format --check . && ruff check .`, `pytest -q` (полный), `make lint`, `make test`, `docker compose config`, при возможности `make all` на реальных данных (или объяснить, что заблокировано человеком: разметка/верификация).
7. Отчёт `docs/qa/review_round1.md`: таблица находок `severity (blocker/major/minor) | модуль | файл:строка | описание | предложение`; итог по G8/G9; список того, что не проверялось и почему. Ничего не исправлять в чужих директориях — находки маршрутизирует координатор.
